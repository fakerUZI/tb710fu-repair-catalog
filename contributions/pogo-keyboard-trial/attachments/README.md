# TB710FU 磁吸键盘实机测试

此条目供带联想原装三触点磁吸键盘、运行 `7.2.6-tb710fu-20261118` 内核的平板试用。先保存工作，吸上键盘，再在修复助手「更新仓库」后单独下载并运行「磁吸键盘实机测试（60 秒）」。有条件时可以保留 USB 连接以方便查看系统状态。

顶排默认按键帽执行音量、麦克风静音、亮度和截图功能。单独按 ★ 切换顶排功能键模式，再按一次切回。在 GNOME Wayland 下，全屏键切换当前窗口全屏，分屏键将当前窗口平铺到左侧。测试结束会恢复原有桌面快捷键。若上次强制关机打断了清理，同一账号下重新运行此条目会先恢复上次的设置。也可用 `TB710FU_FIX_ACTION=rollback` 单独恢复。

测试窗口内，请在空白文本编辑器试字母和 Delete，点击亮度、截图、全屏、分屏、★ 和左下角四格键，再试触控板和拔插。请发回修复助手的功能键记录和实际表现。脚本会检查键盘和触控板是否被识别，日志会记录功能键码和 Delete，普通文字输入无需提供。四格键的实际键码待这轮实测。

脚本在内存应用临时设备树，通过系统已有的 RPMh 驱动启用原厂设备树对应的 PM8550B 电源轨。3.3 V 供电使用 3.296–3.300 V 请求范围，允许 Linux 选择 LDO8 的 3.296 V 档位。退出时释放本次供电请求，并通过调压框架恢复原电压。仅在 `gpio-keys` 原先已绑定时才临时重绑音量键和合盖检测。原先未绑定时，设备树覆盖只启用 UART。退出时按逆序卸载，核对设备树并恢复测试前的绑定状态。遇到暂缓探测或串口未就绪时，运行记录会附上可读取的相关内核日志。测试期间可能发生按键暂时无响应或系统卡住。系统若卡住，重启会回到正常启动流程，测试模块没有开机服务。

使用 `TB710FU_FIX_ACTION=check` 可以只检查当前内核、设备树、供电配置和模块。匹配已核对设备树的平板使用随包 DTBO，其他兼容布局需要 Ubuntu 的 `device-tree-compiler`。随包和现场生成的 DTBO 都兼容启动设备树没有符号表的平板。驱动沿 Pogo UART 控制器查找 TTY 子设备，兼容内核添加的串口端口层级。失败时，运行记录会指明串口查找、打开、配置或发送唤醒的阶段。串口就绪表示主机已发送唤醒，键盘和触控板仍需通过输入设备识别和实际按键验证。

两个模块由当前适配内核的配置和 `Module.symvers` 本地重编译，源码见条目目录中的 `source/`。键盘驱动来源为 `kisodev/android_kernel_lenovo_sm8650` 的 `5cd19e48fb9578d781c931de085f5b0d03cd6cde`，经社区投稿移植后调整了 UART、供电和退出流程。已通过设备树合并、模块构建、隔离退出/回退及平板只读检查。按键、触控板、拔插和挂起唤醒仍需要带键盘实测。
