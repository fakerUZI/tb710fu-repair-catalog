# 20261117 相机清晰度、自动对焦与第二后摄

本修订继续使用 `7.2.6-tb710fu-20261117`，不替换 Image、日期内核分片或 boot，不刷写固件/GPT。新增同 ABI 的 GC02M1 传感器模块及可移除覆盖；libcamera 为用户态软件包更新。前摄既有私有模块和寄存器表不发布、不替换。

## 使用

下载并验证本条目的全部附件，仍通过第一项、唯一的内核修复入口：

```bash
sudo env TB710FU_ATTACHMENTS_DIR=/path/to/attachments \
  TB710FU_KERNEL_ACTION=camera-check bash /path/to/script.sh
sudo env TB710FU_ATTACHMENTS_DIR=/path/to/attachments \
  TB710FU_KERNEL_ACTION=camera-install TB710FU_KERNEL_USER=ubuntu bash /path/to/script.sh
sudo env TB710FU_ATTACHMENTS_DIR=/path/to/attachments \
  TB710FU_KERNEL_ACTION=camera-rollback bash /path/to/script.sh
```

旧 `flash-*` 动作仍提供硬件/应用补充；`camera-install` 另外安装与当前 Ubuntu 包 ABI 匹配的增益修复，因此建议相机问题使用此动作。它不会执行完整内核升级，也不会绕过当前内核、boot、固件、GPT 或文件指纹检查。

## 拍照与自动对焦

主后摄 OV13B10 使用已验证的 GT9772B 马达控制接口，补上基于画面梯度的自动对焦：打开相机、点击预览或拍照前扫描；先粗扫、细调、复核，镜头位置仅在原接口已有的 0–1023 范围内，底层继续分步缓动。每次移动后丢弃排队帧并等待稳定，取三帧中值。暗场、缺少纹理、平坦响应、明显场景变化、超时会恢复原位置并提示；它不是持续追焦、人脸追焦或相位对焦。

默认启用“拍照前自动对焦”；拖动手动滑杆会关闭该选项。前摄和微距为固定焦点，隐藏马达操作。沿用系统已有的活动本机桌面会话规则，开放这个有范围校验的对焦参数；权限在登录后由会话服务授予，登录界面保留 root 所有者，不把媒体设备或任意 sysfs 改成全局可写。

主后摄和前摄全幅 JPEG 为 4200×3120；微距为 1592×1200。保存前预热从三帧增加至十二帧，保留空白帧拒绝、尺寸/完整性校验、0600 临时文件及原子保存。数字放大为裁切，4× 的主摄照片实际只有 1050×780；按钮显示真实保存尺寸，不将数字放大当作光学变焦。拍摄细节优先用 1×，并保持充足光线与稳定画面。

## 第二后摄

重新核对当前 vendor 分区、OEM MTP 设备树及运行内核：原厂配置标为 `topaz_*_gc02m1_macro`，CCI1 master0、地址 0x37、MCLK3 24MHz、GPIO109 reset、CSI PHY3 单 lane。L4B/L15B 均 1.8V，L14B 2.8V；不改变供电电压。单 lane 链路频率 336MHz；时序像素率按原厂 HTS=2192、VTS=1268 与约 30.2fps 推得 84MHz，用于曝光时间换算。独立上电读取实际 ID `0x02e0` 成功后才进行流测试，没有盲扫地址或试猜供电。

传感器输出 1600×1200 RAW10，SoftISP 的有效 RGB/JPEG 为 1592×1200（行缓冲有对齐填充）。首次 transport 测试八帧约 30fps；随后的软件 ISP 测试已出彩色画面。新增驱动包含当前 OEM 模式的通用寄存器值、曝光与 1–12× 增益控制；未读取或发布 EEPROM、设备专属校准或身份数据。原始 vendor 镜像、完整传感器模块二进制、诊断照片与现场 GPT 均不在配套中。

它是约 200 万像素固定焦点微距，不是广角/长焦，也不能用于改善主摄远处细节。对物体需靠近到合适距离；准确最佳工作距离、色彩与低照度尚需实景校准。

## libcamera 用户态修复

五个运行包共同更新为 `0.7.0-1ubuntu2+tb710fu20261117.3`：libcamera0.7、libcamera-ipa、libcamera-tools、libcamera-v4l2、gstreamer1.0-libcamera。源包是当前 Ubuntu `0.7.0-1ubuntu2`，源码与 Debian 打包校验分别为：

- orig.tar.gz：`ebd90a3aa2ca87a39323ffb7a4f5bbf72090b43a2431133759620b63e982db87`
- debian.tar.xz：`0ee3195d74ad85b089c62eb7b2904023f8556544b2d9dbcc67aa834ddde5a09e`

目录提供完整四个补丁：OV13B10 128 code = 1× 的增益与静态属性，两个本机 RAW 驱动的 Q10 增益换算，以及 SoftISP AGC unity 阈值修正。该阈值必须保持真实倍数；把寄存器 code=1 误当成 1× 会导致最低增益时无法继续降低曝光。前摄 1024–8192、微距 1024–12288 是各驱动的控制范围，不宣称完成厂商 ISP 调校。IPA 与库按同一构建一起安装，包含匹配签名，不混装单个 IPA。

安装前核对包名、版本、架构、原软件文件完整性和锁定状态。十个 deb 同时提供原 Ubuntu 版本及新版本，离线可回退。安装设置五分钟回退 timer；前后摄各 30 帧、插件与增益 helper 加载通过才撤销 timer。软件安装验证失败会回退，不能把这个 timer 当作内核冻结、断电或无法启动的救援。

## 恢复与边界

原应用/服务首次快照仍在 `/var/backups/tb710fu-flash-camera-20261117/`；新增文件会补充记录，但不覆盖旧快照。未知修改或备份损坏会阻止覆盖。软件包状态在 `/var/backups/tb710fu-camera-isp-20261117/`，完整安装和恢复载荷在前者的 `payload` 下。

```bash
sudo python3 /var/backups/tb710fu-flash-camera-20261117/payload/install-camera-quality.py rollback --user ubuntu
```

回退恢复原应用/服务、删除本补充新增文件并恢复原 Ubuntu libcamera；不会删除照片，也不刷写 boot。运行态媒体图重建会短暂停止 PipeWire/WirePlumber，并按原活动状态恢复；其他相机进程占用时，模块卸载应失败，不能强拆。

软件自动对焦和更充分的拍照预热能处理失焦与启动瞬态，不能消除暗环境的物理噪声，也不代表已有原厂降噪、镜头阴影、色彩矩阵或多摄融合。GC13A2/GC02M1 的色彩仍用未校准 SoftISP。GNOME Snapshot 的同步硬件闪光问题保持原边界，见 README.md。

## 本次验证

- 算法九项、安装/回退十一项、软件包事务五项、媒体服务恢复三项、会话对焦权限三项测试通过；libcamera IPA 七项（含三种传感器真实增益 helper 的往返换算）通过。
- 五个新运行包在独立容器联合安装、依赖检查和回退原包通过；实机曾因媒体注册检查过早触发安装回退，原包与文件恢复成功。已修正异步枚举等待，并对停在 deactivating 的音频服务加入有限等待，只结束已经在停止的媒体服务，按原活动状态恢复。
- 主摄在受控失焦位置 128 起步，自动选到 704；该固定场景的梯度分数从约 0.00962 到 0.01376，约增 43%。这是单场景算法证据，不是通用画质提升百分比。
- 主后摄→前摄→微距→主后摄→前摄→微距六次预览和完整 JPEG 通过；测试照片为临时文件，已清理。保留拍照黑帧、预热、尺寸及原子保存回归。
- 正常重启后六项相关服务均 active，LED 初始关闭，三路重新枚举；boot A/B、固件与 GPT 对照不变。登录界面保持 root 的对焦权限，活动本机用户的授权由既有会话服务负责。
- 相机预览增加有上限的无帧恢复：六秒无新帧时最多重新连接两次，再给出重开提示；切换、关闭和失败会取消未完成的对焦。

Ubuntu 后续软件更新可能覆盖此本地 libcamera 构建，需重新适配；不锁定系统软件更新。未来日期内核仍须重新编译/审核这些外部模块，服务不会在其他内核版本上强行加载。

微距稳定性边界：重复“前摄全幅拍照→微距预览”测试出现首开无帧，基础对照为 3/4 次直接成功；单独增加 20ms 初始化等待未消除该问题（8/12 次直接成功），因此该候选已撤下，没有并入发布模块。应用六秒无帧自动重连已在实机恢复微距，并完成全部六步拍照；这条 CSI3/SoftISP 路径仍属实验适配，不能声称每次首开均稳定。后续需要继续排查底层启动时序。
